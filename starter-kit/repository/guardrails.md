# Project boundaries

Adapt these starting boundaries to your project's actual policies before adopting the kit.

## Local work

Read and edit only within the task's scope. Preserve unrelated changes. Inspect scripts before running them when their side effects are unclear. Use documented disposable test data for local tests.

## External changes

A request to inspect or draft work does not authorize publishing it. Confirm the target and task authorization before external tracker writes, deployment, data mutations, or permission changes. Prepare a reviewable draft or command when authorization is missing.

## Sensitive information

Keep secrets and private operational data out of specs, tickets, examples, logs, and committed files. Reference the approved credential mechanism without copying its contents.

## Project decisions to fill in

Specify which actions agents may run, which are read-only, and which require a human or CI. Name the relevant environment, data, migration, and deployment procedures. These templates do not grant additional permissions.
